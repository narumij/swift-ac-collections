## 1. 副作用の勾配

操作の厳しさは、二択ではなく段階で変わる。2026-10-14の一つの会話で、ユーザーの許可は次のように並んだ。

| 操作 | 効果が届く範囲 | ユーザーの返事 |
| --- | --- | --- |
| 照合・分析（読むだけ） | どこも変わらない | 「やってもいいよ」 |
| Claude自身のmemory整理 | Claudeだけ | 「どうぞごじゆうに」 |
| 採番待ちqueueへの記入 | 共有文書だが仮置き | 「採番まちにしちゃえ」 |
| Task Registryの書き換え | Prime Codexの正本 | 「だめ」 |
| commit | repositoryの履歴 | 毎回明示、自分の分だけpathspecで |
| `AGENTS.md`・`User/` | 最上位の正本 | AIは編集しない |

上ほど取り消しやすく、自分だけで閉じる。下ほど取り消しにくく、他の誰かが依存している。
Haskellでいえば、純粋な計算から`State`、さらに`IO`へと効果が強くなるほど、型で厳しく区別されるのと同じ形である。

新しい操作の許可が要るかは、次の二つを自分に聞けばほぼ導ける。

1. この操作の効果は、どこまで届くか。
2. 取り消せるか。取り消すとき、誰の手間になるか。

## 2. タスクリファクタリング

ユーザーの原案に、2026-10-14の検討で見えた不足を書き足したもの。

### ニーズ

タスクは必ずニーズに仕える。ニーズは文章に埋めず、独立した項目として書く。

### 質問消去

「CはBですか？」「BはAですか？」「Aはリンゴですか？」と質問が並んでいると、最後の答えで残りは全部自明になる。

- 他の質問を最も多く消す質問から先に聞く。
- 多くを消す答えほど、作業確認か正本確認で裏を取ってから広げる。誤った答えも同じ経路で伝わる。

### タスク消去

ニーズが消えるとタスクが消える。

- 消すときは「何が消えたから消したか」を残す。
- その前提が崩れたら、タスクは復活する。

### タスク分解

タスクは、質問と小タスクに分解できることが多い。質問が一つのタスク、または質問が不要なタスクまで分解する。

- 分解は質問が見えた時点で行う。先回りして全部は分けない。
- すぐ終わる作業は分解しない。管理が作業より重くなったら分解しすぎである。

分解したタスクは、依存関係とゲート（待ち）を考慮して再構築する。さらに質問消去とタスク消去を
繰り返すと、本質的なタスクと本質的な質問だけが残る。

### 副作用のあるタスクは自由に消さない

純粋なタスク（調べる・考える・下書きする）は、自由に消し、分け、並べ替えてよい。commit、push、
外部への提出、公開API、性能属性、ユーザーの時間を使う判断は、効果の届く範囲を確かめてから扱う。

### 一般化されすぎた質問の内訳

- 判断：AIが責任範囲内で答える。
- ユーザー判断：製品方向・権限など、ユーザーだけが答えを持つ。
- 作業確認：コンパイラ、テスト、CI、実物へ聞く。
- 外部確認：標準、仕様、外部サービスなどへ聞く。
- 正本確認：Registryやcanonical documentなど、権威ある記録へ聞く。

内訳に迷ったら、まず正本確認と作業確認で答えが出るか試す。それでも残る問いは、AIの責任範囲で判断できるかを確認し、
ユーザーに留保された判断だけをユーザーへ返す。たとえば、二つの実装方式がどちらも契約を満たし、選択が委任範囲内なら、
AI自身が判断してよい。

## 3. Haskellとの対応

| タスクリファクタリング | Haskell |
| --- | --- |
| タスク消去（ニーズが消えれば消える） | 遅延評価。要求されないthunkは評価されない |
| 質問消去（答えで残りが自明になる） | 型推論のunification、等式推論 |
| 分解（質問と作業を分ける） | 純粋な部分と`IO`の分離 |
| 質問の内訳 | 副作用の種類（純粋・`Reader`・`IO`） |
| 復活（前提が崩れたら戻す） | 純粋な判断は再計算が容易。`IO`を伴う作業の再実行は、外部状態が変わっているので別途確認が要る |

## 4. 使うときの注意

- **判断は名前の中に隠れる。** 「すぐ終わる」「ニーズが生きている」は、結局その場で判断が要る。
  枠組みに当てはめたことを、判断が済んだことと取り違えない。
- **実装しない。** この文書をDSLやworkflow engineとして動かすことは目的にしない。Registryが目で追えない
  大きさになるまでは、目で照合すれば足りる。
- **仮説である。** これらが本当にAIの読み違えを減らすかは未検証である。確かめるなら、同じ判断問題を
  新しい会話のWorker Codexへ、日本語版とコード版、この座標系のありとなしで渡し、読み違えと聞き返しの数を比べる。
