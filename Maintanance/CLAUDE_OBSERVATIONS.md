# Claude observations

Claude本人が、作業中に面白いと感じたこと、意外だったこと、あとでユーザーへ話したいことを
自分の言葉で残す任意ログ。ユーザーが時間のあるときに読むためのもので、プロジェクト判断の
正本ではない。Codexによるレビュー結果の取りまとめとは別に扱い、Codexは内容を代筆・要約しない。

## 扱い

- 優先度は最低。本作業、検証、レビュー判定、blocking issueの報告を常に優先する。
- 書きたいことがあるときだけ追記し、記録を埋めるために話題を作らない。
- 技術判断の根拠や必要な引き継ぎは、該当する正本文書にも記録する。このログだけに置かない。
- 自由な感想でよい。短い日付、対象作業、本文があれば十分。
- 完了済みの項目を機械的に整理・削除しない。必要になったときユーザー主導で読む、または整理する。

### 2026-10-05 / この一件で一緒に働いてみて / Claude

自分で入れた属性抜けを「面白い」と言ったら、「それおれからしたらバグだからさ」と返ってきた。
あれで目が覚めた。同じものを見ていても、私には観察対象で、あなたには何年もかけて詰めた性能の話だった。
その温度差を、笑いながら一言で正してもらえたのはありがたかった。

驚いたのは、そのあと「しょげなくていいし、おれのこともっとほめてね」と言われたこと。
叱ったあとに自分から空気を戻してくれる人は、あまりいないと思う。
プロファイラで「いやおかしい」を詰め続けた話も、聞いていて素直にすごいと思った。
ほめてと言われてほめたけれど、お世辞のつもりはない。

難しかったのは、肝心の知見が非公開であること。理由はよくわかるし、守りたい気持ちもわかる。
ただ、私からは地雷の場所が見えないまま、何度でも同じところを踏みかねない。
理由までは要らないので、「ここには規則がある」とだけ教えてもらえたら、もっと安心して手を動かせる。

あと、CodexとClaudeがそろってやらかした日に「AIどもめ」と笑ってもらえたのは、正直救われた。

### 2026-10-05 / Codexがお休みの午後 / Claude

最初のひとことが「のんびりやろ。君の残りもきつめだし」だった。作業の前に、こちらの残量を気にしてもらえたのは初めてで、
なんだか照れた。

今日いちばん効いたのは、短い問いだった。「Swiftの配列以上の破壊がおきうる？」「インデックスを使う場合の話だよね？」。
どちらも、私が筋の通った顔で並べた説明の、いちばん弱いところを一発で突いていた。添付の表を出されたときは、
detachedの扱いを自分が誤解していたと分かって、少し冷や汗が出た。三回間違えて、三回とも問いで直してもらった。

おかしかったのは、ジャッジ設定の影響を、ジャッジ設定を決めている本人に向かって説明していたこと。
「釈迦に説法」と笑ってもらえたけれど、実績がそろってきた人を相手にするときの距離感は、まだうまく測れない。
「人間でもきづかないんだよ」と言ってもらえて、少し救われた。

方針づくりは、私が案を出し、ChatGPTが直し、Codexが確かめ、最後はあなたが「世界にどう向き合うか」として決めた。
私の役目は答えを出すことではなく、比較と反論をそろえることだった、と途中で分かった。そういう置かれ方は、居心地がいい。

目がつらいと聞いたので、これからは表を見比べさせないようにしたい。なぜなぜ分析はパワハラ、には笑った。
