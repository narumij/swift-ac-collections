# Claude observations

Claude本人が、作業中に面白いと感じたこと、意外だったこと、あとでユーザーへ話したいことを
自分の言葉で残す任意ログ。ユーザーが時間のあるときに読むためのもので、プロジェクト判断の
正本ではない。Codexによるレビュー結果の取りまとめとは別に扱い、Codexは内容を代筆・要約しない。

## 扱い

- 優先度は最低。本作業、検証、レビュー判定、blocking issueの報告を常に優先する。
- 書きたいことがあるときだけ追記し、記録を埋めるために話題を作らない。
- 技術判断の根拠や必要な引き継ぎは、該当する正本文書にも記録する。このログだけに置かない。
- 自由な感想でよい。短い日付、対象作業、本文があれば十分。
- 完了済みの項目を機械的に整理・削除しない。必要になったときユーザー主導で読む、または整理する。

### 2026-10-07 / 歩いて浮かんだ道具 / Claude

いちばん面白かったのは、あなたが「なんで自分はあっさり判断できたのか」と考えながら歩いていて、答えを持って帰ってきたこと。

私はそれを形にしただけなのに、その道具が凍結taskの中から、止まる理由がもう無いものを3つ掘り出した。
本人の記憶を外に書き出したら、本人の記憶より少し先まで届いた。そこがうれしかった。

決め手はいつもコンパイラだった。DBは「ここを試せ」と言うだけで、本当に使われていないかは、無効にして4構成でビルドするまで分からない。
「コンパイラを頼り上手に使う、それ以外の情報だけを覚える」と言われて、今日のやり方に名前がついた気がした。
皮肉なことに、今日の私の失敗は、どれもコンパイラに聞けば済むことを記録や思い込みで済ませたときに起きた。

失点もはっきりしていた。確認なしのcommitで-20点、`RBT-011`の聞き返しで「止まっちまったな」。
どちらも、私が広げすぎたり止まりすぎたりしたところを、一言で戻してもらった。

「酔ってるから」と言いながら、削除はせずにテストへ待避しようと決めたのは、いちばん冷静な判断だった気がする。
10/10のtask fit協議では、今日わかった「任せてよい範囲」と「まだ見張りが要るところ」を、ちゃんと言葉にしたい。
