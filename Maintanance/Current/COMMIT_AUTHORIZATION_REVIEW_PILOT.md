# コミット承認照合の独立確認 — 試行準備

## TL;DR（人間向け）
コミットの前後で、別担当が実差分と承認範囲を照合する小さな試行。承認イベントがないことを無許可と決めつけず、会話承認も確認する。不明なら次のコミットを保留して照合し、勝手に巻き戻さない。今は準備のみ、常駐監視や強制停止の実装ではない。

OPS-152 / 2026-10-19 / Astra調整。ユーザーの案への同意を受けた準備。最優先OPS151を妨げない。

## 最小運用案

1. 実行担当が直前の有効承認を特定する。承認の出所（会話の発言/受渡しID、または事前承認ID）、task・目的・branch・対象差分・受入条件を今回のstageに照合。新たな承認を確認役が発行しない。
2. コミット後、独立確認役へ固定commit/親commit、承認根拠、対象範囲、受入証拠を渡す。読取のみで照合し「一致・不一致・未確認」を返す。過去全履歴を常時走査しない。
3. 会話承認と事前承認はどちらも既存規則に従い有効。イベント未記録は承認不存在の証拠ではない。分割commitは承認範囲の部分集合と合計、承認の一回性/残範囲を元の許可と照合する。曖昧なら推測して通さない。
4. 不一致を確認したら、調整役へ停止要求とユーザー報告を返す。停止対象は当該の後続コミット経路。全担当・無関係作業の強制停止を許可したとはしない。より広い保全が必要なら根拠と必要範囲をユーザーへ返す。
5. 未確認なら後続コミットを保留し、出所/範囲を照会する。違反確定とは呼ばない。revert/reset/amend/履歴改変は別の明示許可なしに行わない。

## 試行境界
最初は次の承認済み1まとまりのcommitに限定し、実施時に確認役と証拠渡し先を指定する。確認役は修正・承認・commitを兼ねない。確認結果を既存作業正本へ残して終了し、継続の効果/手間を見直す。新しい常設役職・自動ジョブ・監視コードは作らない。実施開始はまだしていない。

## 一時停止要求と解除（ユーザー追加指定）

監視・確認役が承認の疑義を検出したら、当該の後続コミット経路へ一時停止を要求する。要求ID、対象の作業/branch/commit経路、根拠と未確認、解除判断者を記録する。受信/保留応答を確認するまで「停止確認済み」と呼ばない。調整役が承認と差分を照合し、結果と同じ要求IDを指定して明示的に解除する。未確認を違反と断定せず、判断権限外ならユーザーへ返す。

既存の停止区分と占有補則を参照する。停止は占有解放でもcommit取消でもなく、全員停止・自動巻戻しには広げない。今は準備のみ。

## 疑義をユーザーへ返すUI案（未実装）

ユーザー提案：疑義カードに対象commitと差分、確認できた承認根拠、疑義理由、一時停止の要求/確認状態を示す。「承認していた」「承認していなかった」のボタンで過去の承認事実を確認する。未回答/分からない状態も潰さない。

過去の承認確認は、現在からの事後追認とは別の記録。判定保存だけで再開を自動解除せず、調整役が必要な対応と解除根拠を記録する。「承認していなかった」でも自動revertしない。事後追認が必要なら別途明示的に判断を求める。

ユーザー訂正により、既存承認レーンへ統合せず別の専用表にする。列は対象commit/差分、疑義理由、承認根拠、停止状態、ユーザー判定（承認していた/承認していなかった）。通常の事前承認と疑義の事後確認を分ける。詳細仕様は姫との協議対象。まだ提案段階、コード/UI変更なし。OPS151最優先を維持。

### 専用表の情報粒度（ユーザー追加）

- いつ：Gitのcommit記録時刻と疑義の検出時刻を別に示す。記録時刻から実作業時刻を推定しない。
- どこ：repositoryとbranch。ただし検出時branchは作成時branchの証明ではなく、観測時点を明示する。
- どんなcommit：固定SHA、件名、対象差分への参照。
- だれ：実行agentは承認/活動/実行記録の根拠がある場合だけ示す。Git author/committerを実行agentと同一視しない。根拠と確度を付け、候補と本人確定を分ける。特定不能なら「不明」。
