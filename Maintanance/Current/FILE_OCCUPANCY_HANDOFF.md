# 停止・再開時のファイル占有

## TL;DR（人間向け）
停止は占有の解放ではない。担当交代は、停止確認と途中差分の確認を済ませ、旧割当を失効させてから新担当へ渡す。専任役は増やさず、明示委任された調整担当が受渡し窓口を兼ねる。

OPS-145 / 2026-10-19ユーザー整備依頼。翻訳は停止維持。文書運用のみ、ロック機構・UI実装は対象外。

## 運用案
1. 既存の依頼正本に、依頼ID、担当（同名なら会話・agent識別子）、編集対象ファイル／節、割当の版または識別子、現在の占有状態を記す。別の全体台帳は増やさない。共有ファイルは原則一人、節分担は対象の非重複と書込み方法が確認できる場合のみ。
2. 停止要求中は解放しない。停止確認後も「停止中・占有保持」とし、本人も新たな再開指示なしに編集しない。他担当も停止を理由に編集しない。
3. 交代時は停止確認の根拠、途中差分・未完操作・原文控えを確認する。必要なファイルのhash等で受渡し時点を固定し、旧割当の失効と新割当を同じ受渡し記録で確定する。停止を確認できない担当と同じ対象へ新規編集を割り当てない。
4. 再開担当は最新の割当と停止後の変更を照合する。古い依頼・記憶だけでは書き込まない。差異や他者編集を見つけたら上書き・復元をせず調整担当へ返す。
5. 受渡しの確定窓口はユーザーが明示委任した調整担当。調整担当の交代も明示して窓口を重複させない。これは内容の決定権や他者成果の自由な編集権を与えない。
6. 強制停止では本人による記録を待たず、停止操作を行った担当が確認できた事実と未確認を代理記録できる。本人の最終申告は改変しない。停止要求だけ・応答なしを停止確認と呼ばない。
