# メンバー表示：ユーザー指示による逐次作業

## TL;DR
ユーザーがその都度指図し、Astraは指示された作業だけを実施する。次の工程や完成形をAIが先回りして決めない。

## 進め方
- 一度に実施する範囲は、その時点のユーザーの明示指示だけ。
- 指示された範囲が済んだら止め、結果をユーザーへ返す。追加実装・調査・委任を自発的に広げない。
- サブエージェントは停止を維持し、再起動にはユーザーの指示を待つ。
- 本番反映・コミットは今回のタスク登録に含まない。

## 現在地
登録時点では次の作業指示待ち。後続のユーザー逐次指示による実施分は下記「代理Solによる後続作業」を参照。OPS-199はユーザー撤回・コード巻き戻し済みであり、旧依頼や受入を引き継いで再開しない。

## 経緯
ユーザー「タスクあたらしくしよう」に続き「俺が指図するから、それをすすめるだけのタスクにして」。以前の要求は背景として参照できるが、AIが工程化して自動実施する根拠にはしない。

## 代理Solによる後続作業（2026-10-21）

ユーザーから関連タスクの正本へ作業を追記するよう依頼され、同じメンバー表示を扱うOPS-200へ後続分を記録する。タスクの過去工程を再開するものではない。担当は各指示を実施した代理Sol。

| ユーザーの逐次指示 | 実施と結果 |
| --- | --- |
| 予定出勤者の右上に×を付けて消したい | index.work.members.jsの予定カードに削除ボタンを追加。既存POST /members/planned/removeを使用。予定だけ外すため、未出勤なら非表示、出勤中なら予定外の赤枠となる。 |
| 予定出勤へ「代理そる」を追加 | POST /members/planned/addで追加し、GET /membersのplannedMembersで確認。コード固定値ではなく本番の稼働状態を操作。 |
| 予定メンバー優先、そのあとは登録順 | MemberState.snapshotが既に返す予定登録順→予定外参加登録順を使用。ブラウザー独自のstableMemberOrder適用を外した。 |

確認：隔離実DOMで予定カードだけに×があること、クリックで該当カードを外せることを確認。隔離モデルで後から予定メンバーを足しても予定群の登録順となることを確認。本番8088にページ更新で反映。試験のために本番メンバーを削除してはいない。
