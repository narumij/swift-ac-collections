# 仮契約概念の導入検討

2026-10-17 / OPS-070 / 作成：Astra。ユーザー依頼による検討タスク登録。親OPS-044。状態はTask Registryを正本とする。今回は登録のみ、調査・制度導入は未着手。

## 発端とユーザーの意図

Registry Studioは半分PoC・半分スケルトンとして、問題を解消できるかと答え候補を維持できるかを並行評価するものだった。AIが着手許可を方式確定と読み替え、全タスクを完遂すべき本契約のように扱うことで負担を増やした。整理で不要・重複と分かることも正常な成果として扱いたい。

ユーザーが示した判定の考え方は「知らなくて当たり前が含まれていたら基本的に仮契約」。整理・試作などの種類を列挙するだけではなく、仕事の前提にある未知を扱う概念である。未知が判明した際のタスク分解・組み替えも自走できるようにしたい。最初の分解を固定し、毎回ユーザーへ手続き判断を戻すための仕組みではない。

ただし影響がまだ読めないため、今回は導入ではなく検討タスクとする、というユーザー判断を記録する。

## 検討範囲

- 「知らなくて当たり前」の未知と、既存正本を確認すれば分かる事項の区別。知らないことの証明や過剰探索を要求しない。
- 仮にする対象（範囲・方法・分解・工程・配置）と、維持する確定事項・権限・安全上の制約の境界。
- 未知が判明した際に自走できる再分解・統合・不要部分の整理と、目的・方針・委任を変えるためユーザー判断へ返す部分の区別。
- PROPOSED/ACTIVE等の状態、DECISION/EXECUTION/DISCOVERY、既存の依存・受入・EXCLUDED・占有権との重複や矛盾。新しい状態や項目を増やす必要があるかも未決。
- 見直しのきっかけ、止め方、成果と理由の残し方。仮契約の終了を成果・証拠の消去や自動的な権限変更にしない。
- 少数の対象で試す場合の範囲・観測点・中止条件と、管理負担が増えないか。

## 完了条件と返却

導入による効果・影響・危険な解釈、既存制度で足りる部分、未決の判断点と限定試行案を整理し、ユーザーが導入可否を判断できる材料として返す。必要なら導入判断・実装を別taskへ切り出す。調査結果の受入と制度の採用を区別する。

既存taskを仮契約へ一括変更せず、上位文書や権限規則を変更しない。本書自体は自律的再分解の新しい許可ではない。具体的な調査開始は現在の依頼・割当に従う。
