### 1. 定義案：寿命は「何が変わったら終わるか」で決める

経過時間ではなく変化で決める（判断座標草案「時間ではなく変化量」、旧`../Archived/JudgmentCoordinates/CHANGE_KNOWLEDGE_LAG_DRAFT.md`と同じ立場）。

| 寿命 | 対象 | 終わる変化 | 例 |
| --- | --- | --- | --- |
| 情報 | 観測された事実（ある時点で何がどうだったか） | 観測対象そのものが変わる | 「ci.ymlのASan jobに`--traits`がない」はci.ymlが変わると終わる |
| 知識 | 事実から得た理解・推論・適用範囲 | 前提か適用範囲が変わる | 「Linuxの成功はmacOSの成功を証明しない」はプラットフォーム差の前提が変わるまで続く |
| 判断 | 見立て・選択（仮判断）と、事実に裏付けられた決定 | 仮判断：見直しのきっかけ（新しい事実・期限・上位判断の変化）。裏付けのある決定：裏付けの事実が変わる | RBT-048の「案Aが筋」は0.7.0の判断時まで。「`@retroactive Comparable`は0件」は誰かが足すまで |

### 3. 記録の分け方（最小案）

| 寿命 | 置き場 | 書き方 |
| --- | --- | --- |
| 情報 | 表面の「点検事実」 | 「これを見れば今も成り立つ」の1行（ファイル:行、コマンド）。観測日と版を添える |
| 知識 | 表面（短く）または長命な正本・Rules | 適用範囲（版・環境・前提）を必ず添える。縮約で範囲を落とさない |
| 判断（仮） | 表面の「見張る」 | 見直しのきっかけを書く。占有者を書く |
| 判断（裏付けあり） | 表面には点検事実だけ | 本文・導出はgitの過去へ。糸口（`git log -- パス`と最後の版）を1行 |
| 契約 | Registry（正本）。文書は参照だけ | 写す場合は「Registry照合日」を添える |
| 経緯 | git | 表面から糸口でたどれるようにする |

原則：寿命の違うものを同じ文・同じ欄に置かない。長命な記録から短命な置き場へリンクしない（短命な置き場へ向けるなら、移動時に直す糸口を残す）。

### 4. 見直しのきっかけ

| 寿命 | きっかけ |
| --- | --- |
| 情報 | 観測対象のファイル・CI定義・toolchainの変更（gitの差分で機械的に拾える） |
| 知識 | 前提の変化（新しいプラットフォーム、版の更新）、反例の報告 |
| 判断（仮） | 書いておいたきっかけ（期限・事実・上位判断の変化） |
| 判断（裏付けあり） | 点検事実が成り立たなくなったとき |
| 契約 | 委任の返却、条件成立、taskのDONE、上位契約の変化 |

taskがDONEになった時は、その正本の情報・判断（裏付けあり）をgitへ沈めて表面を作り直す自然なきっかけ（OPS-072試行2の観察）。
