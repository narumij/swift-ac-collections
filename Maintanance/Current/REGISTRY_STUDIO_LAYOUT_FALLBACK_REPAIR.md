# OPS-116 見取り図の骨格配置崩れ

## TL;DR（人間向け）

依存追加で後続タスクが未配置となり、見取り図全体が通常の依存配置へ崩れる原因を再現・修正した記録。下側前提の列を続ける限定実装を、旧版との比較と回帰検査で技術受入した。Safariや保存中編集版の見え方、上側・routeからの後続は保証範囲外で、旧smokeの環境不足は別の保守候補として残す。

## 依頼

1. 固定版Registryから生成したデータで、全体・HEADから・0.6.0/0.6.1の版表示を確認する。画像の選択版・編集版は未確定なので、再現しなければ正本データでの限界を返し、ユーザーの編集版を勝手に捨てない。
2. fallbackの原因を未配置・辺の順序・矩形の衝突等へ切り分け、具体的なノード/辺を記録する。可能なら固定版差分から最小再現へ縮める。
3. 実辺・条件・状態・版配置を変更せず、影響群に限定した配置修正を行う。骨格の横並び、単独上側、複数下側・共通水平オフセット・不足幅確保の既存要求を保持する。
4. 修正前に失敗し修正後に成功する回帰検査をverify.cjsへ追加する。現実のIDだけに固定しないfixtureも含める。全接続ノード、辺の保持、重複・重なり・順序、各表示範囲を確認しsync/verifyを実行する。

fallback自体を無条件に止めたりvalid()を弱めるだけの修正はしない。原因が既存要求だけでは決まらない場合は、その判断点を返し、全面レイアウト再設計へ広げない。
