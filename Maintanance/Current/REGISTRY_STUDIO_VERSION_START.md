# Studio：版のSTARTと開始側タスクの配置

2026-10-17 / OPS-069 / 作成：Astra。親OPS-048。状態の正本はTask Registry。今回は修正依頼タスクの登録まで。未着手・他担当へ未発注。

## ユーザーと確認した意味

STARTはその版の作業区間の入口。前版のリリース完了の証拠でも、個別タスクの着手許可でもない。STARTから始まる仕事を骨格の上、ENDへ合流する仕事を下に置き、最初にユーザーと調整した配置を接続の意味から再現する。個別IDによる位置指定を増やさない。

## 発端

PERM-079が独立欄から消え、0.6.0のENDへの接続により0.7.0ゲート側に表示された。タスク本文は0.5.4リリース完了後の再開判断、接続条件文は0.6.0完了後のままで食い違っている。STARTの導入で開始側の所属を表現する。

## 改修範囲

- 版フォルダごとのSTART識別子と、版内のSTART・途中カード・ENDの構造を定義し、MilestonesのREADMEと生成器に反映する。既存GATEの版間接続・HEADによる表示境界と整合させる。
- START→タスク、タスク→ENDを扱えるよう、JSON生成、接続・つなぎ替え・除去・保存・取込の経路を揃える。線の種類は増やさず、条件文を保持する。
- START側の仕事は上、END側の仕事は下へ自動配置する。双方へ接続する場合や分岐・合流でも欠落・重なり・循環を検査し、既存配置への影響を確認する。
- PERM-079はSTART-0.6.0からの開始側接続へ移し、条件文をタスク本文の0.5.4完了後の再開判断に合わせる。ユーザー判断待ちを維持し、調査やmergeを開始しない。
- 既存の仮配置・凍結・ユーザー専任・個別の開始条件は変更しない。別タスクの接続を意味の推測だけで一括移行しない。

## 受入条件

生成・画面・保存JSON・正本への取込でSTARTの意味が一致し、版の絞り込みでも開始側タスクを見失わないこと。START側上段とEND側下段を代表例で確認し、重複・不明端点・循環の拒否、同期検査とブラウザ表示を確認する。既存データの扱いを明記し、ユーザー判断・未確認事項の欠落や自動着手への読み替えがないこと。実装時に新しい方針判断が必要なら、その点だけユーザーへ返す。
