# Studio 作業進行帯（OPS-110）

2026-10-18 Astra設計。親OPS-048。ユーザーから軽い設計・委任・試作を依頼。追加要望は他操作へ影響しないリアルタイム表示とタスク番号。

## 初回の契約

- ヘッダー付近のコンパクトな帯にタスクID、短い仕事名、担当、現在工程、更新日時を示す。
- 準備→作業→確認→受入→コミット待ちの現在位置。必要なら待機理由。RegistryのACTIVE等とは別の実行状況。
- 調整担当が進行記録を更新し、画面は約3秒ごとにその記録だけを読む。AIプロセスの生存・実進捗を自動推定しない。
- 保存済み編集版や差分に混ぜない。定期取得で全体render・sync・リロードをしない。選択・入力・未保存編集・スクロール・フォーカスを維持する。
- 通信不調は帯だけに表示し、最終記録を保持。古い記録を現在の稼働保証としない。ファイルなしは未登録表示。
- 初回は一つの作業。進行記録はGit対象外Cache/RegistryStudio/work-progress.json。正式な成果・状態は本書とRegistryに残す。更新手段と書式をREADMEに記載。

## 依頼と境界

作業Sol：RegistryApp内の必要な実装・限定テスト・READMEのみ変更可。サーバーに固定パスの読み取り専用エンドポイントを足してよい。入力検証・安全な文字表示・並行取得防止・非表示時の取得抑制を含める。キャッシュをsyncが消さないこと。製品Sources、Registry、Rules、他の管理正本、Inbox保存機構は変更不可。commit・サーバー再起動・画面操作なし。新しい判断や範囲外問題は返却して止める。

確認Sol：実装後に独立して上記契約と変更を照合し、検証する。修正せず指摘を返す。Astraが最終受入。
