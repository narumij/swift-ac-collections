# Release 0.7.0

最終更新: 2026-10-15 / Codex

## 現在の状態

0.6.0 release完了待ち。これはactive release Registryではなく、0.7.0のrelease検討を開始するための
入口と判断境界を保持する文書である。現時点ではrelease候補commit、製品上の到達範囲、version固有要件、
branch方式、必須gate、tag位置を確定しない。

`_ReleaseTask/`へ人間向け工程表をコピーする前の段階では、release、branch作成、commit、tag、push、公開を
許可しない。

## Release検討開始条件

0.6.0 releaseが完了し、その完了証拠と0.6.0へ含めた範囲・後続へ残した範囲が現行記録から確認できることを、
0.7.0のrelease検討を始める前提とする。

前提が満たされたことだけでは、0.7.0の開始、到達範囲、残taskの採用、凍結解除は成立しない。ユーザーが
`RELEASE-079`を明示的に再開した後、0.6.0後の公開面、残課題、品質・文書状態を判断材料として揃え、
0.7.0へ含める製品上の到達範囲とrelease作業を開始するかを一つの判断として確定する。

## 開始判断までの依存

0.6.0のrelease作業が具体化した時点で、その完了を表すtaskと証拠の置き場を確認し、必要なら通常Task Registryの
`RELEASE-079`へ必須依存を接続する。現時点では0.6.0の完了taskが存在しないため、架空のtaskや依存辺を作らない。

0.6.0から後続へ残したtaskは、その状態、担当、再開条件を維持する。0.7.0の候補になり得ることを理由に、
`FROZEN`を解除したり、`PROPOSED`を採用したり、`USER_ONLY`へ着手したりしない。

## Release作業の起動

開始条件に到達し、ユーザーが`RELEASE-079`を再開したら、次の順序で起動する。

1. 0.6.0の完了記録、以後の差分、未完了task、品質・文書状態を確認する。
2. 0.7.0へ含める変更と後続へ残す変更、version固有要件の候補を分ける。
3. ユーザーへ、0.7.0の製品上の到達範囲とrelease作業を開始するかを一問で確認する。
4. Yesの場合だけ、`../User/RELEASE_PROCESS.md`を`_ReleaseTask/`へコピーし、versionを実値へ置き換える。
5. 確定したbranch方式、必要な品質gate、version固有taskを人間向け工程表と通常Task Registryへ反映する。
6. release中の状態と証拠は人間向け工程表と各工程の正本へ記録し、完了または中止時に本書と通常Task Registryへ還元する。

人間向け工程の正本は`../User/RELEASE_PROCESS.md`とする。release専用Task Registryを別に作らない。

## 0.7.0固有要件

現時点では確定していない。0.6.0の未完了事項や既存taskを、そのまま0.7.0の必須要件へ昇格させない。
開始判断のための照合で必要性、影響範囲、担当、受入条件を確かめ、独立した仕事が必要な場合だけ通常Task Registryへ
追加する。新しい製品判断または公開上の選択が見つかった場合は、推測で埋めず判断taskへ分ける。

## 権限境界

- 0.7.0の製品上の到達範囲とrelease検討開始はユーザーが決定する。
- branch作成、commit、tag作成は、それぞれ直前にユーザーの明示許可を得る。
- candidate branch push、GitHub merge、tag pushはユーザーが実行する。
- Codexは各報告後に対象commitまたはrefをremoteから確認してから後続へ進む。
- release pageやその他の公開操作を行う場合も、対象を示して別途判断する。
