# SolのOJT試行：ユーザー判断

## TL;DR（人間向け）

Solへ小さい実務を渡すOJTの試行範囲を、ユーザーが決めるための資料。末尾では読み取り一件と検査説明の補正一件を限定承認して実施した経緯へ接続している。ユーザーがFableを使うヒントを得る目的であり、継続拡大・製品変更・モデルの恒久学習を認めたものではない。

OPS-107 / USER_ONLY / 判断担当：ユーザー。親：OPS-103。
2026-10-18ユーザー指示で登録。今回は登録のみ。

## 発端と試行案

[初回比較実験](AI_RESEARCH_FIRST_EXPERIMENT.md)で、新しいCodex会話へ課題を渡して回答を取得できた。これを実務でのOJTへ使う案。小さい仕事をSolへ渡し、Astraが成果を確認し、具体的なフィードバックを返し、同じ会話で再挑戦してもらう。得られた知見は受入後に正本へ戻し、次の会話への引継ぎ材料にできるかを見る。

モデル自体の学習・恒久的な能力向上を意味しない。今回の比較実験ではOJTは未実施。実験済み6会話は元の証拠として保持し、試行するなら別の会話を使う案とする。

## ユーザーが明かした目的

2026-10-18ユーザー補足：隠れ目的は、ユーザー自身がFableをうまく使いこなすためのヒントを抽出すること。SolへのOJTは、そのためにAstraの仕事の渡し方・確認の仕方・フィードバック・止め方を観察できる機会として位置づける。

試行する場合は、単にSolが仕事を終えたかだけでなく、どの説明・分割・境界の提示や訂正が役立ったか、ユーザーが再利用できそうな具体例を残す。Solで観察したこととFableへの応用仮説を区別し、Fableにも同じ方法が効くとは未検証のまま断定しない。この補足は目的の記録であり、試行開始やFableへの依頼の許可ではない。

## ユーザーが決めること

- 試行するか、いつ行うか。
- 対象とする小さい実務と、Solへ任せる範囲。
- Astraの確認・フィードバック・再試行の区切り、回数や使用量の上限。

上記は判断材料であり、今すぐ回答する必要はない。AIは本体の着手・委任・催促をしない。依頼された整理などの補助だけを行う。実施承認後に必要な作業タスクを切り出し、依頼・編集範囲・受入条件を固定する。現時点で会話作成やSolへの依頼は行わない。
