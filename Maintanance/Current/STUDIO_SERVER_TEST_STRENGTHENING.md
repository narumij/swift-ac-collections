# スタジオサーバーのテスト増強

## 目的と現在地
2026-10-21 ユーザー依頼「サーバーのテストコード増強タスクを切ろう」。指定チームで着手後、ユーザーの中止指示により停止。途中変更は保持し、受入・コミットは未実施。
サーバー側の期待する動作をテストで固定し、状態更新・通知・保存の回帰を早く検出する。テスト件数や網羅率そのものを目標にしない。

## 作業範囲
1. 既存テストと公開操作を対応付け、不足する契約を短く列挙する。
2. メンバー状態、作業カード・承認のViewModel、変更通知、連絡・待機・全員通知のうち、不足するモデルテストを追加する。
3. HTTP境界は入力拒否、状態への反映、再送時の重複防止など、モデルだけでは確かめられない接続に絞る。

期待値はユーザー要求と既存の確定した契約から定める。実装の出力を写すだけのテストにしない。代表的な正常系・境界・異常系を、小さい独立したケースで確かめる。通知については発行・受信と実際の状態反映を区別する。

## 境界
隔離した一時DB・一時ファイル・試験サーバーを使い、本番DBや稼働メンバーへ通知しない。画面変更、機能追加、設計変更、既存不具合の修正、本番反映はこのタスクに含めない。不具合を見つけた場合は失敗するテストと再現条件を返し、期待動作が未確定なら判断点として返す。

## 受入条件
追加したテストがどの要求を守るか分かること。対象の振る舞いを壊した場合に失敗することを代表例で確認すること。既存試験への影響と実行結果を示し、実在する不具合による失敗を隠さないこと。画面確認は必要な接続の軽い確認までとする。
