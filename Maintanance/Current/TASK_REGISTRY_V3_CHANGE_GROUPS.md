# V3の複数task変更群

## TL;DR
保存に複数taskの編集があっても、taskごとの変更群として照合し、競合した群を残しながら独立した群を反映できるよう隔離実験を拡張する。本番接続はしない。

OPS-168 / EXECUTION / Astra調整・姫 / OPS-167 K1 / 2026-10-19継続指示。

## 実装契約
対象は複数taskのstate/ownerのみ。一つのtaskの変更欄は一群として原子的に反映する。保存IDと群ID、要求内容を固定して再送を識別する。ユーザー/調整役が選択した群だけを適用し、未選択・競合・反映済み・拒否を区別して返す。成功群が再送で二重反映されないこと。同一群IDで内容を変更した要求は拒否。

世代違い、必須baseline欠落、重複、不正保存は全体拒否。未対応の構造/提案編集混在も今回の区切りでは全体拒否を維持し、別群として勝手に処理しない。対応欄だけの複数taskは独立群として扱える。全群成功でない保存を全体反映済みと記録しない。

実験folderのadapter/harness/test/READMEのみ姫が編集する。既存単一task試験とWebKit試験の互換を保つ。試験はA成功+B競合、A再送、B再検討は新要求、未選択群維持、同一task複数欄全取消、旧世代全体拒否を含む。実server/DB/Inbox/templateは変更しない。返却は連絡DB、Astraが受入/正本/Registry/commit。
