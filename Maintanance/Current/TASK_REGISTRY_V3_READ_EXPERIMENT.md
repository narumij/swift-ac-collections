# Registry V3 隔離DB読取実験

## TL;DR
設計案を小さな隔離実験で確かめる。構造・順序・HEADによる読取範囲が保存できることを試す。本番DB、Studio、現行正本のデータは変更しない。

OPS-160 / EXECUTION / Astra調整・姫。2026-10-19ユーザー「いえす」により実装承認。

## 範囲と受入

設計元は[TASK_REGISTRY_V3_DESIGN.md](TASK_REGISTRY_V3_DESIGN.md)の「既決事項の回収と設計調査の結論」。明示順fixtureを使い、汎用folder比較方法や到達状態の新規規則は決めない。

成果は `Maintanance/RegistryApp/Experiments/registry_v3_read/` の独立コード・fixture・再現手順。SQLiteはメモリ内または実験専用一時領域のみ。現行server/import/syncの実装は変更しない。更新/採番APIと本番移行は範囲外。

正常構造、未接続・末尾ゲート・任意ゲートID、カード順、現在区間/全体、境界端点、グラフ区別、重複/端点欠落/循環の拒否を試験する。共通部分のみ現行readerと照合し、既知の実装差は仕様期待値を使う。期待値を実装自身から生成するだけの検査にしない。

姫は実験フォルダを担当。Astraは正本とRegistryおよび独立受入を担当。返却は連絡DB。commitはAstra。

## 受入結果（2026-10-19 Astra）

初回返却 LTR-20261019-13C1C26F383B4CAFA437BE110E21984A、補正返却 LTR-20261019-DB5F68BD042C49CDA71EBB831B00FF49 を受入。実験コード4ファイルは指定フォルダ内。本番実装・データは変更していない。

Astraが初回17試験を再実行して成功。ただしowner欠落fixtureを独立に試すとKeyError後にトランザクションと2ノードが残った。姫へ修正を依頼し、全例外時のrollback・不明scope拒否と回帰試験を追加。最終20試験をAstraが再実行して全て成功、diffチェックも成功した。

確認範囲：構造・明示順・現在範囲・全体範囲・境界端点・管理と進捗の区別。共通部分は現行sync.buildと比較。任意ゲートID・欠落ゲート・末尾ゲートは原型仕様の期待値と照合し、現行readerとの差を明示。異常入力後の全取消と同じ接続の再使用も試験した。

限界：完全なデータ移行ではない。条件/Flowは格納のみで読出し比較対象外、正本リンク・恒久属性・派生DONE等も範囲外。current読取でも出典表は全件返す。未配置taskはallのみ。この結果を本番フォーカスAPIや完全互換snapshotの受入へ転用しない。

OPS-160は本実験の範囲でDONE。次の候補は属性の完全性と出典の範囲限定を含む読取契約、その後に採番・更新・競合の隔離試験。本番切替は未実施。
