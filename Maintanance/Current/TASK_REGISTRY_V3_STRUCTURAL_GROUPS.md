# V3保存の構造変更群

## TL;DR
Studioで編集した辺の差分を、基準値付きのDB更新へ接続する。「相談待ち」は勝手に確定せず保存に残す。曖昧なつなぎ替えを推測しない。隔離実験のみ。

OPS-170 / EXECUTION / Astra調整・姫 / OPS-167 K1/K2接続 / 2026-10-19継続指示。

## 最初の区切り
姫は、現行保存に何が残るかを読み、progress辺とmilestone linkのadd/remove/set/rewireをどこまで一意に復元できるか、ファイル単位の内訳を返す。実装はAstra確認後。task変更群OPS-168と構造API OPS-169を再利用する。

保存の前後だけで削除と追加の対応が曖昧なら、勝手につなぎ替えとしない。明示的な操作指定や確認待ちとして残す案を示す。複数構造変更が互いに依存する場合、個別適用の順番で意味が変わることに注意し、必要な群を原子的に扱うか未対応を明示する。

conditionReviewは未適用編集の状態。相談結果の制約文と根拠を明示して渡す経路を設計し、保存しただけで解除しない。旧基準/重複/未知端点/循環/未採用方向は黙って変換しない。固定save/group識別と再送、未選択/相談待ち/競合/成功の分類を保つ。

今回の範囲は実験folderのみ。版/カード編集、提案採番、親子UI変更、恒久区分、本番切替は別。現用template/server/DB/Inboxは変更しない。返却は連絡DB、Astraが記録と受入とcommit。
