# V3とStudioの隔離接続

## TL;DR
DBの内容をStudioで表示・編集・保存・再開できるか、実運用とは別の環境で確かめる。最初は接続契約と変更内訳を確認する。実サーバーや保存済み編集は変更しない。

OPS-165 / EXECUTION / Astra調整・姫 / 2026-10-19ユーザー継続指示。

## 目的と境界
OPS-162の工程3。OPS-163の固定写しとOPS-164の世代・改訂を利用し、表示用データと編集の基準を区別する。旧source.sha256にDB改訂を偽装しない。現行Markdown/フォルダが正本のまま。新しい本番仕様の採用ではない。

## 最初の区切り
姫は現行Studioの入力・保存・再開・三者比較を読取調査し、隔離adapterの契約とファイル単位の変更内訳を連絡DBで返す。実装前にAstraが受け入れる。既存の調査は再利用し、全体再探索は不要。

必要な検討：DB由来の意味属性と出典、版所属/順序、明示状態と表示上の派生状態、退役task、境界参照、DB世代/改訂と対象値を持つ編集形式、旧保存の明示拒否または固定manifestによる対応。未対応操作を隠さず、最小の端から端までの試験範囲を提示する。

## 検証と停止点
表示・編集・保存・再開・最新値との三者比較を隔離fixtureで確認する計画とする。同一値/別欄変更/同一欄競合/世代変更のケースを含める。実装前の返却では、今のコードで可能な範囲と追加判断が必要な範囲を区別する。

本番server起動・停止・再起動、実DB・Inbox・workspaceへのアクセス変更、ユーザー画面操作、現用templateやsyncの変更は禁止。この区切りは読取と提案だけ。調査対象の実装ファイルは読める。正本・RegistryとcommitはAstra担当。
