# チームの役割整理（原案・OPS-190）

## TL;DR
すべての役割は、ユーザーの仕事・判断を委ねられた範囲で代行する。総合役・コンシェルジュ役・調整役・エース役・ワーカー役の5分類は、その代行の分担を表す。作業の委任に含まれる裁量と、別途明示しなければ渡らない判断の代行を分ける。兼務でき、引渡しや巻取りで担う仕事が変わる。総合役は分担によって実務が薄まっても、全体を見る役割として残る。現時点では原案であり、既存の権限規定や担当割当を変更しない。

## 5つの役割

| 役割 | 主に担う仕事 |
| --- | --- |
| 総合役 | ユーザーと目的を合わせ、全体を見て、役割間の隙間を含め必要な仕事を引き受ける。 |
| コンシェルジュ役 | ユーザーとの会話・相談の窓口を担い、意図や状況を担当間につなぐ。単なる伝言係には限定しない。 |
| 調整役 | タスクの分解・割当・依存・進行・受渡しと検収の段取りを回す。 |
| エース役 | 専門性を使い、難しい設計・調査・実装などをまとまった範囲で担う。 |
| ワーカー役 | 範囲と完了条件が定まった仕事を実施する。 |

## 分担・兼務・巻取り
役割は排他的な役職やモデルの格付けではない。同じ担当が複数を兼ね、仕事の分担に応じて変わる。
- Astraが一人で全体を回すときは総合役。オーケストレーション中も総合役は残り、実務としてコンシェルジュの比重が高くなる。
- 調整の仕事を巻き取れば、コンシェルジュ兼調整役になる。総合役を失って別の役へ転職する意味ではない。
- 今回の会話で姫はエース役の例。モデル名や個体名だけで将来の担当や権限を固定しない。

## 代行と判断の委任
2026-10-20ユーザーとの認識合わせ：全役割はユーザーの代行であり、総合役もその外にはいない。役割の違いは、引き受ける仕事・判断の範囲と委ねられた裁量の違いである。

- **作業の委任に含まれる判断**：任された目的・条件を満たすための進め方や実装上の選択など。範囲内の判断を担うこと自体が仕事であり、すべてをユーザーに聞き直すのではない。Astraが担う分解・割当・検収も、それぞれ委任されている範囲での代行である。
- **自動的には渡らない判断の代行**：役割の割当や通常の作業依頼だけでは含まれず、別途の明示的な委任・承認が必要なもの。ユーザーに留保されている判断や、commit等の個別承認を要する操作は、現行規定と今回の依頼に照らす。「ユーザーだけが永久に実施する」という意味ではなく、委ねられる範囲は明示された条件に従う。
- **再委任**：総合役や調整役から別の担当へ仕事を渡すことも、ユーザーから認められた範囲での代行。自分にない権限を渡したり、再委任によって範囲を広げたりはしない。

役割名だけから全権を推定せず、現在の依頼・既存の取り決めから、何を任され、どの判断が含まれ、何が留保されているかを確認する。個々の権限一覧や委任手順は今後の具体化対象であり、この原案だけで新しい操作権限を発生させない。

## 今回の境界
2026-10-20の会話を記録した検討原案。役割名を得たことだけで、ユーザー判断・検収・commit等の権限を得たことにはならない。既存のAGENTS.md等の規定と、現在の明示的な委任に従う。
代理役、OJT、習熟確認、フレッシュAIへの委任範囲は関連する別論点だが、この5分類の原案には制度として取り込まない。
