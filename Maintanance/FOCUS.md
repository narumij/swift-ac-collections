# フォーカスを中心とする情報設計原型案

2026-10-18 / Astra / ユーザーとの対話に基づく草案。現行規則の追加や変更ではない。

## 目的と仮説

情報を残すことと、今その情報を扱うことを分ける。判断の根拠を失わず、現在の目的に必要な情報へ集中できるようにする。

仮説：何かにフォーカスすると、今は扱わなくてよいものが決まる。それが「忘れる」の最初の仕組みになる。ここで忘れるとは削除ではなく、通常の探索対象から外すことをいう。古い情報を一律に捨てることではない。

[DESIGN.md](DESIGN.md)は構造設計の原型仕様であり、本書はその構造上で情報をどう扱うかの案である。同書のカード・対話・管理・活動・キャッシュという情報種別を置き換えない。以下は、それらにまたがる役割を示す。

## 五つの役割

| 役割 | 残すもの・担うこと |
| --- | --- |
| 正本 | 決定・事実・権限・条件の根拠。何についての正本かを明確にする。証拠や提案を決定と混ぜない。 |
| 関係 | 依存、順序、所属とその条件。配置を組み替えても判断の意味を保てるようにする。 |
| 現在地 | 今の目的、選択中の仕事、ゲート。通常どこまで追えばよいかを示す。 |
| キャッシュ | 現在の範囲で使う判断と根拠への入口、保留、再確認の契機。読む・再計算する負担を減らす。 |
| 再探索条件 | 前提変更、矛盾、根拠不足など、通常の探索境界を越える必要が生じる条件。 |

正本とキャッシュは同じ決定権を持たない。キャッシュには写しのほかに解釈や確認の手掛かりも入りうる。次の行動に影響する箇所で区別し、キャッシュの文言から新しい許可や禁止を作らない。

## 情報の流れ

1. 今の依頼と現在地から、答える問いと必要な範囲を選ぶ。
2. 範囲内の正本・関係・利用できるキャッシュで仕事を進める。現在の状態や操作権限は、その正本で確かめる。
3. 根拠が足りない、矛盾する、前提が変わった場合は、必要な範囲だけ探索を広げる。境界を越えること自体は禁止しない。
4. 新しい判断や事実は適切な正本へ残す。今後の再探索を減らせるものを、必要に応じキャッシュへ反映する。
5. 現在地が進んだら、次の仕事に必要な情報を選び直す。以前の情報は保存されていても、通常は追わなくてよい。

ゲートは工程上の条件に加え、ここまでの判断を使って先へ進める探索境界にもなる。ただし、ゲート到達を自動着手・合格・権限付与とは扱わない。ゲート以前でも、現在の仕事に効く制約と根拠への入口は引き継ぐ。

フォーカスは探索の範囲を絞るもので、規則の適用範囲を変えるものではない。今の操作に適用される共通規則は、探索対象の外に置いても失効しない。毎回すべてを読み直すのではなく、操作に応じて必要な規則へ戻れる入口を保つ。

## 更新する契機

- 目的や現在地が変わったとき：扱う範囲と引継ぎが足りるかを見る。
- 決定・条件・依存先が変わったとき：それに依存する記録とキャッシュの該当箇所を見直す。
- 根拠と写しの不一致が見つかったとき：適用範囲を確かめて補正する。全履歴の再探索へ自動的に広げない。
- 探す費用が見込んだ価値を上回るとき：未確認と必要な入力を残して探索を止め、必要ならユーザーへ聞く。

単に古い、長い、最近読んでいないという理由だけでは、失効・削除・再検証を決めない。更新条件を増やすこと自体にも維持費用がある。

## 今回の経験から言える範囲

ゲート、正本、Studio、判断キャッシュにより、現在必要な情報へ直接アクセスする運用が育ってきた。これは対話と運用上の観察であり、削減量を測定した結果ではない。

[判断の出どころの限定試行](Current/JUDGMENT_ORIGIN_CLASSIFICATION_PILOT.md)では、6項目の写しに実装事実や解釈が同居し、共通規則由来の文を独自判断と誤分類する例もあった。一律分類の利点はこの範囲では薄く、実際の退避・復元は未試験である。

ユーザーは、キャッシュ量を減らす仕組みについて「問題がおきるまでこのまま」と判断した。量の制限や自動退避をこの案から始めない。保存量を減らさなくても、普段追う範囲が絞られれば目的を達成できる可能性がある。

## 未確認と評価の観点

- 境界の外にある必要な制約を落とさず、現在地を移せるか。
- 理由を確認したいとき、過去へ低い費用で戻れるか。
- キャッシュの維持費用より、探索・再計算を減らす効果が大きいか。
- 新しい担当でも、全履歴を読まず必要な仕事を開始できるか。

困った場面を材料に、この原型を修正する。分類体系の完成や情報量の削減そのものを目的にしない。
