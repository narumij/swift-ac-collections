# フォルダ表現マイルストーン原型仕様

本仕様では構造設計のみを取り扱う。情報設計は利用者の課題とする

## フォルダ

### hoge

マイルストーン対象フォルダは仮想的に以下のノードを持つ

```
|START-<FolderName>|-----------|END-<FolderName>|
```

以後、STARTをSTART-<FolderName>の短縮表現とする
以後、ENDをEND-<FolderName>の短縮表現とする

GATE-<NextFolderName>.mdをゲートファイルとする
GATE-<NextFolderName>.mdはGATE-<NextFolderName>ノードでもある
以後、GATEをGATE-<NextFolderName>の短縮表現とする

GATEファイルのノード名は識別子であり、必ずしも次のフォルダ名を正確に表す必要は無い。
接続は常にフォルダを名前順にソートした際の現在フォルダの次のフォルダとなる
フォルダの比較方法は利用者が定める

ゲートファイルを配置することでバージョンのゴールが示される
GATEは特殊ノードで、ゲートファイルはフォルダ内に配置しているが、仮想上はバージョンの外に置かれる

一つのフォルダにおけるゲートファイルは一つに制限されていて、複数のファイルがある場合は事前条件違反となる
名前順で最後のフォルダのゲートファイルはどこにも接続されないが、これを許容する

```
|START|-----------|END|-|GATE|
```

フォルダの名前順の次のフォルダが次の版となり、ゲートは次のSTARTに仮想的に接続されている

```
|START|-----------|END|-|GATE|-|START|-----------|END|
```

連続するフォルダ間でゲートが不足している場合、それは版同士の未接続として許容する

### 中間マイルストーン

フォルダ内のファイルはゲートファイル以外は中間マイルストーンファイルとなる。

中間マイルストーンはファイル名順に接続される

```
|START|---|A.md|---|B.md|---|C.md|---|END|
```

ソート制御はファイル名に依存するので、ノード識別子への利用は非推奨となる。ノード識別子はファイル内部に記載する必要がある
この例では中間マイルストーンのファイル名先頭を数字にしないが、フォルダ内のゲートが末尾となる先頭に数字を用いる様式を推奨する

### HEADファイル

HEAD.mdファイルをバージョンフォルダと同階層に設置し、現在のバージョンを記載する

例
```
Milestones/
├── HEAD.md
├── 0.6.0/
│   ├── 10-A.md
│   ├── 20-B.md
│   └── GATE-0.7.0.md
└── 0.7.0/
    ├── 10-C.md
    └── GATE-0.8.0.md
```

### GOALファイル

GOAL.mdファイルはフォルダを維持するための置物であり無視すること
