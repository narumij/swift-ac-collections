# Milestones

**いまは切り替え中。** 到達点とゲートを `Maintanance/MILESTONES.md` などから、このフォルダへ移している途中。移し終わるまでは、古い場所の記述と、ここの記述が両方ある。食い違ったら、どちらかを直さず、ユーザーに聞く。

## 方針（2026-10-17 ユーザー決定）

- フォルダだけで各バージョンを表す。名前が `_` で始まるフォルダ（`_Archived/` など）は除外。それ以外のフォルダには、名前そのままの識別子（END-0.5.4 など）が自動で付く（2026-10-17 ユーザー決定）。
- ゲートのファイルは三つの部分でできている：`# カード情報`（`## ID`・`## 名前`・途中のゲートだけ `## 状態`）、`# 正本`（リンクか「このファイル」）、`# 記録`（`sync.py`は読まない）。正本はカードに含めない（2026-10-17 ユーザー決定）。
- ゲートとして読むのは `NN_*.md`（途中のゲート）と `GATE-x.y.z.md`（版ゲート）だけ。ほかのファイル（`GOAL.md` など）は読まない。
- ファイルだけでゲートを表す。
- フォルダの作成とゲートの新規作成または移動で、バージョン遷移を表現する。
- ゲート同士は常にシーケンス。フォルダ内の最終ゲートはバージョンゲート（`GATE-<次の版>.md`）。それ以外の順序は、ナンバリングのソートで決まる。

ファイルの中には、どの版で実施するかを書かない（置き場所のフォルダで決まる）。識別子はカード情報の ID だけ（StudioのIDと同じ。UUIDは2026-10-17に廃止）。

- 既存のゲートの ID と名前は変えない。版を刻み直すときは、ファイルを動かすだけ。
- 新しいゲートには、新しい ID を付ける。ID を使い回さない。

マイルストーンは並列を扱わない（シーケンシャル制限、2026-10-17 ユーザー決定）。到達点どうしは一本の列で、分かれたり合流したりしない。到達点どうしのつながりは、`RegistryApp/sync.py`がゲートの配置元フォルダとファイル名の行き先（フォルダ内の途中ゲートは番号順）から作り、`RegistryApp/verify.cjs`が一本の列であることを確かめる。

**マイルストーンとゲートの作業は、必ずユーザーが同席する。AIに一人ではやらせない**（2026-10-17 ユーザー決定）。そのため、カードに担当は書かない。

つながりの決まり（2026-10-17 ユーザー決定）：版ゲートに入るのは、そのフォルダの END からだけ。タスクとENDの接続はTask Registryの「マイルストーン接続」に明記する。`sync.py`はその行を読み、接続先や方向を暗黙に付け替えない。途中のゲートにはタスクが直接つながってよい。

済んだかどうか（2026-10-17 ユーザー決定）：版ゲートと END は `HEAD.md` の現在地から決まるのでチェックを持たない（現在地以下の版ゲート、現在地より前のフォルダの END は済み）。チェック `- [ ] DONE` は途中のゲート（`NN_*.md`）にだけ置く。現在地より前のフォルダの途中のゲートは、チェックがなくても済み。

版ゲート（`GATE-x.y.z.md`）の ID は `GATE-x.y.z`、名前は「x.y.z リリース」で、ファイル名と同じ番号にする（2026-10-17 ユーザー決定。ドットは残す）。食い違うと`sync.py`が止まる。途中のゲート（`NN_*.md`）の ID は `MS-*` のまま。

## 置いてあるもの

- `HEAD.md` — 現在地の版。
- `<版>/` — その版のゲート。
- `GATE_TEMPLATE.md` — ゲートのひな形。
- `_Archived/` — 通り過ぎたゲートと、リリースの記録（`_` で始まるので版フォルダではない）。
- `Maintanance/MILESTONES.md` — 報告（現在位置、全体の図など）。ゲートの中身は持たない。

## Studio との関係

Studioの到達点のカードとつながりは、`RegistryApp/sync.py`がゲートのファイルの「カード情報」と並びから作る。「記録」は読まない。ゲートを足す・動かす・戻す・書き換えるのどれでも、`sync.py`を1回叩けば追いつく。止まるのは、ID の重複、カード情報の欠け、正本のリンク切れ、タスクとのつながりの引用が消えたとき、および下記の経路不整合があるとき。

## 計画の組み替え

版フォルダは `END-<フォルダ名>` を持つ。`GATE-<次の版>.md` を置くと、そのフォルダの END → リリースゲート → 行き先フォルダの最初の途中ゲート（なければ END）が接続される。版番号のソート順で接続先を推測しない。

途中に版を挟む場合は、新しい版フォルダを作り、既存のリリースゲートをそこへ移し、元のフォルダに新しい版へのゲートを置く。既存ゲートのIDと到達条件は保持する。移動した文書の相対リンクは新しい配置に合わせる。ENDにつながるタスクは、到達先自体が変わらなければ変更しない。

接続先の不在、複数のリリースゲート、分岐・合流・循環・孤立があれば同期を止める。配置変更は条件の達成や通過を意味しない。計画変更と未達を引き受ける判断を分け、ユーザーの判断を記録する。
