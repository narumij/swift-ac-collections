# Milestones

**いまは切り替え中。** 到達点とゲートを `Maintanance/MILESTONES.md` などから、このフォルダへ移している途中。移し終わるまでは、古い場所の記述と、ここの記述が両方ある。食い違ったら、どちらかを直さず、ユーザーに聞く。

## 方針（2026-10-17 ユーザー決定）

- フォルダだけで各バージョンを表す。名前が `_` で始まるフォルダ（`_Archived/` など）は除外。それ以外のフォルダには、名前そのままの識別子（END-0.5.4 など）が自動で付く（2026-10-17 ユーザー決定）。
- ゲートのファイルは三つの部分でできている：`# カード情報`（`## ID`・`## 名前`・途中のゲートだけ `## 状態`）、`# 正本`（リンクか「このファイル」）、`# 記録`（`sync.py`は読まない）。正本はカードに含めない（2026-10-17 ユーザー決定）。
- ゲートとして読むのは `NN_*.md`（途中のゲート）と `GATE_x_y_z.md`（版ゲート）だけ。ほかのファイル（`GOAL.md` など）は読まない。
- ファイルだけでゲートを表す。
- フォルダの作成とゲートの新規作成または移動で、バージョン遷移を表現する。
- ゲート同士は常にシーケンス。フォルダ内の最終ゲートはバージョンゲート（`GATE_<次の版>.md`）。それ以外の順序は、ナンバリングのソートで決まる。

ファイルの中には、どの版で実施するかを書かない（置き場所のフォルダで決まる）。識別子はカード情報の ID だけ（StudioのIDと同じ。UUIDは2026-10-17に廃止）。

- 既存のゲートの ID と名前は変えない。版を刻み直すときは、ファイルを動かすだけ。
- 新しいゲートには、新しい ID を付ける。ID を使い回さない。

マイルストーンは並列を扱わない（シーケンシャル制限、2026-10-17 ユーザー決定）。到達点どうしは一本の列で、分かれたり合流したりしない。到達点どうしのつながりは、`RegistryApp/sync.py`がゲートの並び（版フォルダの順、フォルダ内はファイル名の順）から作り、`RegistryApp/verify.cjs`が一本の列であることを確かめる。

**マイルストーンとゲートの作業は、必ずユーザーが同席する。AIに一人ではやらせない**（2026-10-17 ユーザー決定）。そのため、カードに担当は書かない。

## いまの列（2026-10-17）

- `0.5.3/` 10_RBT_DOCUMENTS（MS-DOC）→ GATE_0_5_4（GATE-0.5.4）
- `0.5.4/` GATE_0_6_0（GATE-0.6.0）
- `0.6.0/` 10_VALIDATION_REVIEW（MS-VALIDATION）→ GATE_0_7_0（GATE-0.7.0）
- `0.7.0/` 10_SPI（MS-SPI）→ GATE_0_8_0（GATE-0.8.0）
- `0.8.0/` 10_HUMAN_REVIEW（MS-HUMAN）→ GATE_0_9_0（GATE-0.9.0）
- `0.9.0/` 10_QUALITY-0001（MS-QUALITY）→ GATE_1_0_0（GATE-1.0.0）
- `1.0.0/` 到着点。ゲートは置かない（END-1.0.0 だけが自動でできる）。

END-x.y.z は版フォルダごとの集合点で、実ファイルを置かない。`sync.py`が各版フォルダのリリースゲートの直前に自動で置き、リリースゲートへつなぐ（例：`0.5.3/` → END-0.5.3 → GATE-0.5.4）。END は識別子だけで、名前も条件も持たない。

つながりの決まり（2026-10-17 ユーザー決定）：版ゲートに入るのは、そのフォルダの END からだけ。タスクは END につなぐ（タスク→版ゲートはそのフォルダの END へ、版ゲート→タスクはタスク→その版の END へ、`sync.py`が付け替える）。途中のゲートにはタスクが直接つながってよい。

済んだかどうか（2026-10-17 ユーザー決定）：版ゲートと END は `HEAD.md` の現在地から決まるのでチェックを持たない（現在地以下の版ゲート、現在地より前のフォルダの END は済み）。チェック `- [ ] DONE` は途中のゲート（`NN_*.md`）にだけ置く。現在地より前のフォルダの途中のゲートは、チェックがなくても済み。

版ゲート（`GATE_x_y_z.md`）の ID は `GATE-x.y.z`、名前は「x.y.z リリース」で、ファイル名と同じ番号にする（2026-10-17 ユーザー決定。ドットは残す）。食い違うと`sync.py`が止まる。途中のゲート（`NN_*.md`）の ID は `MS-*` のまま。

## 置いてあるもの

- `HEAD.md` — 現在地の版。
- `<版>/` — その版のゲート。
- `GATE_TEMPLATE.md` — ゲートのひな形。
- `_Archived/` — 通り過ぎたゲートと、リリースの記録（`_` で始まるので版フォルダではない）。
- `Maintanance/MILESTONES.md` — 報告（現在位置、全体の図など）。ゲートの中身は持たない。

## Studio との関係

Studioの到達点のカードとつながりは、`RegistryApp/sync.py`がゲートのファイルの「カード情報」と並びから作る。「記録」は読まない。ゲートを足す・動かす・戻す・書き換えるのどれでも、`sync.py`を1回叩けば追いつく。止まるのは、ID の重複、カード情報の欠け、正本のリンク切れ、タスクとのつながりの引用が消えたときだけ。
