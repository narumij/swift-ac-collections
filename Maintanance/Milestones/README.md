# Milestones

**いまは切り替え中。** 到達点とゲートを `Maintanance/MILESTONES.md` などから、このフォルダへ移している途中。移し終わるまでは、古い場所の記述と、ここの記述が両方ある。食い違ったら、どちらかを直さず、ユーザーに聞く。

## 方針（2026-10-17 ユーザー決定）

- フォルダだけで各バージョンを表す。
- ファイルだけでゲートを表す。
- フォルダの作成とゲートの新規作成または移動で、バージョン遷移を表現する。
- ゲート同士は常にシーケンス。フォルダ内の最終ゲートはバージョンゲート（`GATE_<次の版>.md`）。それ以外の順序は、ナンバリングのソートで決まる。

ファイルの中には、どの版で実施するかを書かない（置き場所のフォルダで決まる）。識別子（StudioのID）はファイルの中に書く。

マイルストーンは並列を扱わない（シーケンシャル制限、2026-10-17 ユーザー決定）。到達点どうしは一本の列で、分かれたり合流したりしない。`RegistryApp/verify.cjs`がStudioの到達点の関係で機械的に確かめる。

**マイルストーンとゲートの作業は、必ずユーザーが同席する。AIに一人ではやらせない**（2026-10-17 ユーザー決定）。そのため、カードに担当は書かない。

## 置いてあるもの

- `HEAD.md` — 現在地の版。
- `<版>/` — その版のゲート。
- `GATE_TEMPLATE.md` — ゲートのひな形。
- `1.0.0/END.md` — 終点の印（ゲートではない）。

Studioの到達点のカードは、`RegistryApp/sync.py`がゲートのファイルの「一意識別子」と「カード情報」から作る。「記録」は読まない。ゲートを書き換えたり動かしたりしても、`sync.py`を1回叩けば追いつく（引用の文が消えたときだけ止まる）。
- `Archived/` — 通り過ぎたゲートと、リリースの記録。
- `Maintanance/MILESTONES.md` — 報告（現在位置、全体の図など）。ゲートの中身は持たない。
