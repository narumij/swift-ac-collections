# 受入Codex用ブートストラップ作成task

## 目的

作業Codex、司令塔Codex、または会話のいずれかを失っても、作業成果を独立した証拠から再検収し、
受入可能な状態と不足する状態を区別して司令塔へ返せる、受入専用Codexの起動契約を作る。

## 背景

司令塔と作業者を一体にすると、実行負荷による応答品質低下やconversation喪失時に、作業能力だけでなく
完了条件、証拠の読み方、拒否理由まで同時に失い得る。作業者が再実行可能な成果と証拠を残し、別の受入者が
正本と境界に照らして検収できれば、特定conversationの記憶や人格を完全再現せずに復旧できる。

## 役割境界

受入Codexは次を行う。

- Task Registryと対象taskの詳細正本から、受入条件と権限境界を特定する。
- diff、test、compiler診断、測定、生データなど、taskが要求する独立証拠を確認または再実行する。
- 作業者の完了報告、AI間の合意、test件数だけを受入根拠にしない。
- `受入可能`、`不足あり`、`判断待ち`、`権限外`を区別し、根拠と再現手順を司令塔へ返す。
- 不足の修正を自分で開始せず、実行taskへ戻す。

受入Codexは次を行わない。

- Task Registryの最終更新、commit、push、公開判断を代行する。
- taskの目的、公開契約、優先順位、残余リスクの許容を変更する。
- 作業者の説明を補って、存在しない証拠を推定する。
- 司令塔の人格や関係性を再現できたと主張する。

## 作成するもの

1. 毎回固定して渡す短い受入ブートストラップ。
2. taskごとに渡す受入契約template。
3. 作業者のhandoffと受入結果を接続する最小形式。
4. 受入Codexが停止して司令塔またはユーザーへ返す条件。
5. 別projectで受入・拒否・証拠不足を試すための実験候補。

## 試行場所

司令塔・作業Codex・受入Codexを分ける運用試験は、このrepositoryでは行わない。失敗時に製品作業、
Task Registry、公開契約へ影響しない別projectを用い、三役のhandoffと復旧可能性を評価する。
このrepositoryには、実験から受け入れた結果だけを別判断で戻す。

## 完了条件

- 作業用ブートストラップと責務が重複せず、相互に代替しない。
- 司令塔が失われても、Registryと正本と成果物から受入確認を再開始できる設計になっている。
- 受入Codex単独ではRegistry更新やcommitを行えない境界が明記されている。
- task固有の証拠が不足する場合、推定で完了にせず作業側へ戻せる。
- 別projectでの試行、このrepositoryへの採用、Orientation参照追加、既存運用への切替は、
  このtaskの完成と分離されている。
