# Codex司令塔オリエンテーション 冗長性レビュー

## レビュー状態

2026-10-11、Codexによる独立レビュー完了。

## 目的

フレッシュなCodexが`CODEX_ORIENTATION.md`を全文読み、司令塔として必要な理解と復帰能力を維持したまま、
冗長さを削減できる箇所を独立に指摘する。

目的は文書を短くすること自体ではない。重複、過剰な具体例、同じ意味の反復、他の正本文書へ委ねられる詳細を
見つけ、初読時の負荷を下げることである。

## 対象

- `Maintanance/CODEX_ORIENTATION.md`

## レビュー境界

- Orientation本文は変更しない。レビュー結果は本書だけへ記載する。
- 現在のTask Registry、個別task、Archived記録を調査して内容を補強しない。
- 文書の思想、責任境界、復帰経路、停止条件を新しく設計しない。
- 単に文章が長いという理由だけで削除候補にしない。削った場合に失われる理解を確認する。
- `AGENTS.md`、`TASK_ORIENTATION.md`、`CODEX_TASK_OPERATION_PLAYBOOK.md`などへの委譲を提案する場合は、
  参照先に必要な内容が実在するか確認する。
- 現在状態や履歴をOrientationへ追加する提案はしない。

## 確認観点

1. 同じ原則が複数箇所で実質的に反復されていないか。
2. Orientationに必要な判断原理と、詳細手順・現在状態・歴史説明が混在していないか。
3. 表、箇条書き、本文が同じ内容を重ねて説明していないか。
4. 初回理解に必要な具体例と、別文書へ委ねられる詳細を区別できるか。
5. 短縮によって、責任分担、証拠の限界、停止・復帰、Task Registryの読み方が失われないか。
6. 文書を短くしても、初めて読むCodexが「何を読まないか」を判断できるか。

## 記載形式

指摘ごとに次を記載する。

### 指摘番号・対象節

- **分類:** `削除` / `統合` / `短縮` / `移管` / `維持`
- **冗長だと判断した範囲:** 対象の見出しまたは要約
- **理由:** 何と重複し、またはOrientationの役割からどう外れるか
- **最小修正案:** 削除、統合、短文化、参照先への委譲の具体案
- **失われ得る理解:** 修正時に保護すべき意味
- **確信度:** `HIGH` / `MEDIUM` / `LOW`

最後に、次をまとめる。

- 変更せず維持すべき中核
- 安全に削減できる箇所
- 削減すると役割を損なう箇所
- 推奨する編集順

## レビュー結果

### C-1・「taskと管理面をリファクタリングする」の沿革説明

- **分類:** `短縮`
- **冗長だと判断した範囲:** Task Registry以前の長文メモから現在の分離構造へ至った経緯（本文84〜109行）
- **理由:** Registry成立の理由を理解する価値はあるが、長文メモの効用、情報増加による負荷、約30%の利用量、第三者agentへのinterfaceという四段の説明が、同じ結論を重ねている。Orientationに必要なのは、短いRegistryが照合結果の圧縮であることと、現在状態・詳細・由来を別の正本へ分離する理由である。
- **最小修正案:** 4段落を2段落へまとめる。残す内容は、(1) Registryは蓄積を捨てず正規化した入口である、(2) 現行taskはRegistryと詳細正本から扱い、Archiveは由来を調べる場合だけ読む、(3) Orientationへ現在状態や履歴を再集積しない、の三点とする。約30%という個別事例は削除する。
- **失われ得る理解:** 短いRegistry行の背後に照合と学習が圧縮されており、過去の蓄積を否定した制度ではないこと。
- **確信度:** `HIGH`

### C-2・「Task処理ポスター」の説明

- **分類:** `移管`
- **冗長だと判断した範囲:** 中間ゴール、task分類、依存辺、goal proximity、cycle時の停止を説明する本文129〜139行
- **理由:** `TASK_ORIENTATION.md`には中間ゴール、`DISCOVERY`・`DECISION`・`EXECUTION`、`SEQUENCE`・`PARALLEL_JOIN`、readyとnext、`DIRECT`〜`OUTSIDE`、cycle時の停止が実在し、より体系的に説明されている。Orientation本文では判断原理への入口があれば足りる。
- **最小修正案:** ポスター画像は維持し、説明を「中間ゴールから必要なtaskを分け、必須依存とgoal proximityからnextを選び、新しい判断点やcycleでは停止して分解し直す」という一段落に短縮する。詳細は`TASK_ORIENTATION.md`と`CODEX_TASK_OPERATION_PLAYBOOK.md`へ委ねる。
- **失われ得る理解:** readyはnextを意味せず、`LATER`・`OUTSIDE`を惰性で進めないこと、およびcycleを辺の無視で解消しないこと。
- **確信度:** `HIGH`

### C-3・「このrepositoryで特に慎重に扱うもの」と「証拠を混同しない」

- **分類:** `維持`
- **冗長だと判断した範囲:** 技術的難所の一覧と証拠表（本文141〜175行）
- **理由:** `AI_TECHNICAL_ORIENTATION.md`には各難所と証拠経路の詳細が実在するが、本節は初読者が通常testのgreenを完成証拠にしないための最小限の警告として機能する。証拠表も、各証拠が示さないものを横並びで示すOrientation固有の要約であり、単なる重複ではない。
- **最小修正案:** 原則として維持する。短縮する場合も技術項目の列挙と「単独では示さないもの」の列を残し、個別契約だけを`AI_TECHNICAL_ORIENTATION.md`へ委ねる。
- **失われ得る理解:** 機能、最適化後の挙動、安全性、性能、文書、履歴、独立確認が代替関係ではなく、別々の限界を持つ証拠であること。
- **確信度:** `HIGH`

### C-4・「復帰手順」と起動規則の反復

- **分類:** `維持`
- **冗長だと判断した範囲:** `AGENTS.md`、Task Registry、選択task正本を順に読む手順と、Maintanance全体を走査しない指示（本文186〜199行）
- **理由:** 「目的と読み方」にも起動順があるが、Orientationの目的には会話や作業場所を失った場合の復帰経路が含まれる。ここを参照だけへ縮めると、初読者がbranch・worktree・CI・Claude assignmentまで含む復帰順を一箇所で確認できなくなる。
- **最小修正案:** 7項目を維持する。冒頭節側の起動説明だけを一文に抑え、詳細な復帰経路は本節へ集約する余地がある。
- **失われ得る理解:** 記憶や古いhandoffから復元せず、現在の正本とgitの事実を優先し、無関係な記録を読まないこと。
- **確信度:** `HIGH`

### C-5・「初回orientationの確認」とtask graph lint具体例

- **分類:** `統合`
- **冗長だと判断した範囲:** 一般的な受入確認4項目に続く、lint固有の確認5項目（本文211〜236行）
- **理由:** 読了と判断能力を区別する受入確認はOrientationに必要である。一方、`TASK_ORIENTATION.md`にも初回確認事例があり、`Graph/TASK_GRAPH_LINT.md`には自動修正しない境界、`WARNING`の扱い、0件の限界、fixture先行が明記されている。Orientationにlintの全設問を複製すると、特定実装の説明が中核原理より目立つ。
- **最小修正案:** 一般的な4項目は維持する。lint例は、機械検査へ任せる構造とCodex・ユーザーへ残す意味判断を説明できるか、という一問と参照先だけへ短縮する。詳細な5問は`Graph/TASK_GRAPH_LINT.md`または`TASK_ORIENTATION.md`側で維持する。
- **失われ得る理解:** Orientationは読了確認ではなく、責任境界、判断の前提、証拠限界を実例へ適用できるかの受入確認も担うこと。
- **確信度:** `HIGH`

### C-6・「詳しく読む場所」と本文中の参照

- **分類:** `短縮`
- **冗長だと判断した範囲:** 本文中ですでに役割を説明した参照を含む11件の一覧（本文238〜251行）
- **理由:** 初回と必要時の読書経路をまとめる一覧には価値があるが、`CODEX_OBSERVATIONS.md`、`REFACTORING_FROM_ATCODER_2025.md`、`RELEASE_CHECKLIST.md`は通常のOrientation読了後に一律で読む資料ではない。列挙が広いほど「何を読まないか」という境界が弱く見える。
- **最小修正案:** 一覧を「初回に読む」「選択taskが要求した場合だけ読む」に分ける。後者の個別文書は代表例を絞るか、選択taskの詳細正本から辿る原則へ置き換える。
- **失われ得る理解:** 思想、task運用、技術難所、現在状態が別の正本に分かれていることと、それぞれの入口。
- **確信度:** `MEDIUM`

## 総括

### 変更せず維持すべき中核

- responsibilityとaccountabilityの分離、およびユーザー・Codex・Claude・第三者AIの責任境界
- Codexが報告を事実・解釈・提案へ整理し、ユーザー判断を残った一件へ絞る原則
- 実行中に新しい判断が現れた場合の停止と再分解
- repository固有の技術的難所と、証拠ごとの限界
- Task Registry、詳細正本、Orientation、Archiveの役割分離
- 正本とgitの事実から復帰し、Maintanance全体やArchivedを走査しない手順
- 読了ではなく実例への適用で理解を確認する考え方

### 安全に削減できる箇所

- Registry成立史のうち、同じ分離理由を重ねる説明と約30%という個別事例
- Task処理ポスター周辺の詳細手順。`TASK_ORIENTATION.md`と`CODEX_TASK_OPERATION_PLAYBOOK.md`に実在する
- task graph lintの5問を、一つの受入観点と参照へまとめた部分
- 読書一覧のうち、選択taskから辿るべき個別・歴史資料

### 削減すると役割を損なう箇所

- 責任分担を示す表と、Codexの委譲範囲
- 証拠表の「単独では示さないもの」
- 復帰手順と「何を読まないか」の明示
- 初回orientationが実践上の受入確認を要するという原則

### 推奨する編集順

1. C-1の沿革説明を圧縮し、Registry・詳細正本・Orientation・Archiveの四分離を残す。
2. C-2のポスター説明を入口へ縮め、実務詳細を既存正本へ委ねる。
3. C-5のlint具体例を一問へ統合する。
4. C-6の読書一覧を初回必須と必要時参照へ分ける。
5. 最後にC-3とC-4が損なわれていないことを確認し、単なる行数削減を目的とした追加削除は行わない。

この順序なら、責任境界、証拠の限界、停止・復帰、Task Registryの読み方を保ったまま、主に歴史説明と他文書に実在する手順の重複を減らせる。
