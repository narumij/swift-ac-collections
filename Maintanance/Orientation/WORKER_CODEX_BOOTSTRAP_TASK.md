# 作業Codex用ブートストラップ作成task

## 目的

司令塔ではない作業Codexへ、repository全体の管理思想やTask Registry運用を背負わせず、
一つの委任作業を安全に完了するための局所的な契約だけを渡せるブートストラップを作る。

これは`CODEX_ORIENTATION_V3.md`の短縮版ではない。司令塔と作業者は役割が異なるため、
作業Codex向けの独立した接続面として設計する。

## 背景

高負荷な技術探索と、状態管理、作業選択、他agentへの発注、受入判断を同じconversationへ
同時に担わせると、技術上の強みとは別に管理能力が圧迫される。完成済みの司令塔向け
orientationを作業者へ一律に読ませることも、認知負荷を増やし、委任されていない管理権限まで
担うという誤解を招き得る。

作業Codexには、全体を管理する能力ではなく、限定された作業を境界内で遂行し、検証可能な
成果と観測を司令塔へ返す能力を求める。

## 作成するもの

次の二層を候補として設計する。

1. 作業Codexに共通する短い固定ブートストラップ
2. taskごとに司令塔が埋める局所作業契約のテンプレート

少なくとも次を表現できること。

- 今回のゴール
- 参照する正本と既決事項
- 許可された変更範囲と対象外
- 停止条件と質問条件
- 必要な検証と提出物
- commit、push、他agentへの発注などの権限境界
- 作業者の終了報告と司令塔による受入完了の区別
- 発見した別問題を勝手に作業へ取り込まず、観測として返す方法

## 作業者に委譲しないもの

- Task Registryの管理または状態更新
- 次taskの選択、分解、優先順位変更
- 中間ゴール、公開契約、品質基準、release可否の変更
- Claudeその他のagentへの独自発注
- ユーザーへ管理操作や工程判断を差し戻すこと
- 許可された範囲外への実装拡張

必要な統合、検収、受入、Registry反映は司令塔が担う。

## 受入条件

- 司令塔用orientationと作業者用bootstrapの責任境界が明文化されている。
- 固定部分とtask固有部分の重複が抑えられている。
- 技術探索、調査、実装、検証の少なくとも異なる二種類の作業へ適用できる。
- 作業者が管理権限を得たと誤認しにくい。
- 作業者が未知の問題を発見したとき、隠蔽も無断拡張もせず司令塔へ返せる。
- 候補文書の完成と、現行運用への採用・参照切替が別の受入境界として扱われている。

## 現在の位置づけ

現在の中間ゴールへは直接寄与しない独立した将来課題である。作業分担が必要になった場面で
再開する。司令塔・作業Codex・受入Codexを分ける実運用試験は製品作業から分離した別projectで行い、
その結果を確認してから、このrepositoryへ採用するかを別途判断する。
