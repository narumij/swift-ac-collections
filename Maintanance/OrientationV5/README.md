## 主な修正

| 論点 | V5での扱い |
| --- | --- |
| 新たな出発点 | 過去の成立史より、現在の需要と到達状態を入口に置いた。過去資料は具体的な問いがある場合だけ参照する |
| 誤り・相談・訂正 | AGENTS候補の「協働の前提」を参照し、訂正と相談が実務につながるよう説明した。独立した道徳規則の一覧は増やしていない |
| 判断を一つかゼロにする | `DECISION`は一つのユーザー判断、`DISCOVERY`と`EXECUTION`はノー判断。新しい判断点が出たtaskは停止し、分割へ戻る |
| 判断と事実確認 | 実物や既決事項で解ける問いを、不要なユーザー判断にしない。一方、「案が一つだけ」から権限を導かない |
| 分解とインライン化 | 境界を見えるように分け、不要な仕事を除き、独立性を失った手順をまとめる。判断・証拠・受入・権限の境界を保つ |
| Haskellと最適化 | 需要からの評価、不要な計算の除去、答えの伝播、分解・インライン化、依存を守る順序変更を、理解を助ける比喩として置いた |
| 効果と権限 | 作用の範囲や戻す手間は慎重さを考える材料。小ささや可逆性から許可を推測しない |
| 担当と成果物 | V4の独立した役割表を外し、現在の依頼とAGENTSへ戻す。受領・管理・編集・採用を分けた |
| 着手と完了 | `SEQUENCE`と`PARALLEL_JOIN`を分け、全依存の完了まで一律に待たせる表現を修正した |
| 読む範囲 | 明示的なオリエンテーションでは三文書、通常の再開では進捗一覧と選択taskを使う。会話消失だけで全文通読を追加しない |
| 作成と採用 | ドラフト完成、正本採用、参照切替、配置変更を別の境界として保った |

## 補足資料からそのまま移さなかったもの

補足資料の比喩を、新しい制度にはしていない。特に次の点は、今回の依頼とAGENTS候補に合わせた編集判断である。

- 「ニーズを独立項目にする」：既存の目的・範囲から分かれば足りるものとし、新しい必須欄は足していない。
- 「純粋なtaskは自由に消し、分け、並べ替えてよい」：計画の検討と、共有物・記録の変更を分けた。下書きや読む作業にも負担や他者の依存があり得る。
- 「前提が崩れたらtaskが復活する」：需要を再評価する意味で取り入れ、自動再開や凍結解除にはしていない。
- 「すぐ終わる作業は分解しない」「委任範囲の実装方式はAIが選べる」：新しい判断点が出たtaskを止める、というユーザーの明示した境界を優先した。
- 過去の一会話における操作と許可の表：現在にも通用する権限表として転記していない。

関連する分解・依存・停止の三資料から、V5の運用に必要な内容はtaskオリエンテーションとPlaybookへ取り込んだ。V5本文は、それらの旧資料を追加の運用規則として読む構成にしていない。由来は調べられるよう、このメモに残す。
