# 共通作業規則

Astra・Codex・Claude・Worker共通。初版：2026-10-16、Astra、OPS-055。継続維持はOPS-044。

起動時の必読資料にはしない。一時作業物を作成・引き継ぐとき、または日終わりの掃除を依頼されたときに、必要な節だけ読む。状態・採番・権限はTask Rulesと現在の委任に従い、本書で重ねて定義しない。環境のアクセス許可を迂回しない。

## 一時作業物を作るとき

/tmp等のシステム一時領域に、task IDや固有名で識別できる専用ディレクトリを作る。既存ファイルとの衝突を避け、作成した担当が、そのtaskの詳細正本または指定された返却欄に次を記録する。採番前の直接依頼は指定のqueue項目に記録する。

| 記録項目 | 内容 |
| --- | --- |
| パス | 作成した専用ディレクトリの絶対パス |
| 作成 | 作成日時（JST）と担当 |
| 用途 | 関連taskと何のための作業物か |
| 状態 | 使用中／削除可／継続保持／削除済み |
| 保持条件 | 残す理由と、削除できる時点または次の確認時点 |
| 証拠の保存先 | 必要な成果・検証証拠を保存した正本または証拠ファイル |

全task分の一覧を本書へ重複して持たない。不要になった時点で削除してよいが、毎回の会話終了前の削除は必須にしない。日終わりに回収できる記録を残す。必要な証拠を一時領域だけに残さない。

## 日終わりの掃除

依頼された掃除範囲にあるtaskの記録から対象を集める。/tmp全体やホーム全体を探索して掃除対象を推測しない。初回導入前の記録されていない作業物は、この手順だけを根拠に削除しない。

1. 現在の作業状態と作成担当の記録を照合する。使用中、保持理由あり、用途や所有が不明なものは残す。
2. 必要な成果・検証証拠が保存されていることを確かめる。別担当のものは「削除可」が記録されている場合だけ扱う。日数やtaskのDONEだけで削除可と判断しない。
3. 記録された専用パスと実物が一致し、共有ディレクトリや別の場所へのリンクでないことを確認する。削除対象はその作業が作成した範囲に限定し、広範囲のワイルドカードを使わない。
4. 削除日時・担当・結果を元の記録へ追記する。既に存在しない場合はその事実を記録する。継続保持なら理由と次の確認時点を残す。
5. 掃除結果は、削除した範囲・保持した範囲・確認が必要なものを簡潔に返す。

共有キャッシュ、DerivedData、通常の.build等は、この一時作業物の掃除対象ではない。別途その範囲の依頼が必要。日終わりの自動実行や常時監視は設定しない。
