# Task Registryの圧縮・アーカイブ手順

現行の記録を軽くしながら、外した内容の原文を後から調べられるようにする。記録を整理するときに参照し、通常起動時の必読資料には加えない。

## 対象と権限

完了・除外の記録、役目を終えた説明や依存辺など、現行から履歴へ移す部分を扱う。古さや長さだけを理由に、未完了の仕事に必要な条件を外さない。

実施範囲は現在の依頼と委任による。文書そのものを移動する場合も、[文書の変更権限](TASK_RULES_V2.md#文書ランクと変更権限)と[配置維持例外](TASK_RULES_V2.md#正本整理時の配置維持例外)を確認する。本手順を読むことだけでは、対象の移動・状態変更・再開の許可にならない。

一時作業物の記録を含む場合は、[共通規則の圧縮時の扱い](COMMONS.md#圧縮アーカイブ時)も確認する。未削除の記録を履歴側だけへ移さない。

## 手順

1. **移す範囲と、現行に残す情報を確かめる。** 対象の記録と、それに依存する仕事を確認する。残る仕事の着手・停止・完了条件、判断・実行権限、未確認事項、必要な前提と証拠への経路を特定する。比較できるよう、移す前の内容を保持してから編集する。

2. **原文をArchivedへ保存する。** `Maintanance/Archived/`の、日付と対象が分かる名前のファイルへ保存する。既存の履歴を上書きしない。対象の本文・task行・依存辺と、意味を読むために必要な見出し・周辺の説明を省略せず残す。冒頭に移動日・元の文書・対象範囲と、移動時点の履歴であることを記す。元の状態、判断理由、未確認事項を要約で置き換えない。相対パスは、移動後も同じ資料を指すように直す。

3. **現行側に原文への道筋を残す。** [Registryの「過去の記録への入口」](TASK_REGISTRY_V2.md#過去の記録への入口)へ、固定ID・何の記録か・保存先へのリンクを残す。同じ保存先の記録は、対象IDが分かる形でまとめてよい。番号のない記録は対象の名前を使う。残るtaskが必要とする条件と参照は現行側にも残す。依存辺を外す場合は、[依存関係の更新](TASK_RULES_V2.md#依存関係の更新)に従い、前提が満たされた証拠か、不要になった理由を辿れるようにする。[採番表](TASK_RULES_V2.md#task-id採番状態)は現行に残し、番号を戻さない。

4. **照合してから、現行から外す。** 保存した原文を移す前の内容と照合し、欠落や意味の変更がないことを確認する。現行側のリンクから対象ID・記録の原文へ進み、そこから証拠の参照先まで辿れることを確かめる。確認できた部分だけを現行から外し、変更全体の差分で、残るtaskの状態・再開条件・必要な依存や参照が失われていないことを確認する。照合できない部分は外さずに残す。

## 圧縮時の振り返りとノウハウ記録

2026-10-16、ユーザー指示により、圧縮・アーカイブをRegistry運用の振り返りとノウハウ追記の機会とする。整理中に見つかった滞留・重複・誤読・判断の記録漏れを振り返り、次の作業に使える新しい知見を[調整ノウハウ](COORDINATION_KNOW_HOW.md)へ日付・根拠・適用範囲付きで残す（恒久task OPS-046）。

既にある知見は重複追加せず、条件や反例が増えた箇所を更新する。新しい発見がなければ追記不要とし、今回の作業報告でその旨を示す。振り返りのためだけに無関係な履歴を掘り直したり、毎回の採点表を増やしたりしない。状態変更・ユーザー判断はRegistryと詳細正本へ先に記録し、ノウハウはそれらの代用にしない。

## 調べ直すとき

現行Registryの「過去の記録への入口」から対象IDや記録名で保存先を絞り、Archivedの原文と、その証拠を読む。現在の状態や権限は現行の記録で確認する。アーカイブされた文書の効力は、[AGENTS.mdの「現在の仕事と正本」](../../AGENTS.md#現在の仕事と正本)に従う。SQLite索引がなくても、この経路で調べられるようにしておく。
