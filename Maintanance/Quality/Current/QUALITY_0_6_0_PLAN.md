# 0.6.0 製品品質試験 — 実施要領（概略）

## TL;DR
0.6.0でswift-ac-collectionsの品質試験を一周する。既存試験と品質要求を起点に、対象版の証拠と残課題を揃える。今回はタスク登録と概略計画のみ。試験開始・製品修正・CI起動はまだ行わない。

QUALITY-006 / PROPOSED / 2026-10-19 ユーザー依頼。所属は0.6.0、接続先はEND-0.6.0。版フォルダのGATE名から対象版を推定しない。

## 対象と基準
- ElementBufferModule、OptionalElementBufferModule、NextPermutationModule、RedBlackTreeCollections（Set / Dictionary / MultiSet / MultiMap）。Studioの試験は対象外。
- [品質要求](../QUALITY_REQUIREMENTS.md)、[4モジュールのProfiles](../README.md#モジュール別の品質プロファイル)、[試験手順](../../Testing/TEST_WORKFLOW.md)、[試験状況](../../Testing/TESTING.md)を起点にする。未決の要求や合格値は勝手に決めない。
- [前回の棚卸し](../0.6.0-1/QUALITY_ASSESSMENT_INVENTORY.md)から未解決だけを引き継ぐ。過去の合格を今回の合格に代用しない。QUALITY-002/003など既存課題の実装は重複して引き取らず、今回の結果から参照する。

## 実施順
1. **準備**：対象commit、Swift/Xcode、OS・アーキテクチャ、構成、比較基準commitを記録。現行CIと既存試験から実行項目・コマンド・合格条件の表を作る。判断未定の項目は保留理由を残す。担当と実行環境を確定してから開始する。
2. **初回横断**：4モジュールの公開契約、Test as Spec、既知課題と試験の対応を浅く確認し、欠落と重複を洗い出す。全実装レビューへ拡張しない。
3. **モジュール別の実行**：既存の通常試験・境界値・所有/寿命・コピー/無効化・Death Testを実施。赤黒木は4型の各結果を分ける。Debug/Release、対応環境のbuildは現行の提供範囲とCI構成に沿う。
4. **横断的な品質確認**：ASan等の既存sanitizer構成とDeath Testを区別して結果を残す。性能は固定した比較元・条件で既存ベンチマークを使い、揺れと再現する退行を分ける。失敗した最初の結果を消さず、再試験理由と結果を併記する。
5. **最終横断・受入**：契約と証拠の対応、環境差、既知不具合、未実施をまとめる。失敗は最小再現・影響・次の担当を記録。修正は別の限定依頼で行い、対象commitが変われば影響範囲の再試験を記録する。

## 証拠と終了条件
計画・実行表・ログ参照・比較結果・残課題をこのQuality/Currentにまとめる。各結果に対象commit、実行条件、コマンド、日時、結果、証拠の所在を残す。環境不足は未実施、基準未定は判定保留と明記する。

計画した項目に合格/失敗/未実施/保留が付き、失敗・保留の扱いと引継ぎ先を調整担当が確認したら試験一周の受入とする。未実施を合格に数えず、タスク完了からrelease承認や品質ゲート通過を自動推定しない。ユーザー判断が必要な残余リスクは分離する。

一式の保存は[Qualityの運用](../README.md)に従い、次の一周開始時に空いている版・回数へ移す。既存0.6.0-1は上書きしない。
