# 候補V2と進捗一覧の整合性確認

確認日：2026-10-14

共通の判断原理と、リポジトリ固有の制度は概ね一致していた。文書の変更権限、開始時の読取範囲、判断と補助の境界に読み違いが生じる箇所を修正した。

## 対象

- [候補V2](AGENTS_SWIFT_AC_CANDIDATE_V2.md)
- 入力の[PROGRESS_OVERVIEW.md](/Users/narumij/Documents/GitHub/swift-ac-collections/Maintanance/PROGRESS_OVERVIEW.md)
- [進捗一覧の修正版](PROGRESS_OVERVIEW.revised.md)

現行のAGENTS.mdも参照した。候補V2の採用や、リポジトリ直下のAGENTS.mdの変更は、この確認には含めていない。

進捗一覧の修正は、ユーザーが指定した元ファイルへ反映済みである。出力フォルダの修正版は、その同一内容の確認用コピーであり、運用上の正本は元のPROGRESS_OVERVIEW.mdに置く。

## 修正した箇所

| 論点 | 照合で分かったこと | 修正 |
| --- | --- | --- |
| 教訓の反映と編集権限 | V2は入口文書へ教訓を反映する一方、進捗一覧はAGENTS.mdをAIの編集対象外とする | V2ではAGENTS.mdへの修正案をユーザーへ返す。作業手順への反映は、その文書の変更権限と委任範囲に従う |
| 開始時に読む範囲 | 「Registryだけ」では、その前にある権限・配置の規定や、後ろの依存関係・運用規則が抜けうる | 両文書で、同じ進捗一覧内の権限・配置、Task Registry、Task precedence、Registry rulesを確認対象とした。他の管理文書を一括で読む規則にはしていない |
| 上位文書の権限 | 作業状態の優先順位と、文書の編集・採用・移動の権限は別である | V2から進捗一覧の既存の変更権限・配置規定を参照。進捗一覧の優先順位も作業状態についてのものと明確にした |
| 採番の正本 | 使用済み番号の上限と採番方法が、すでに「Task ID採番状態」に置かれている | V2にその参照を加えた。番号管理の保留や別台帳は追加していない |
| taskの判断を一つかゼロにする分解規則 | 進捗一覧は意図的に判断を分離しているが、V2の「方法や小さな判断は自分で決める」はノー判断task内でも新しい判断を行うと読める | 進捗一覧の規則を維持し、V2を修正。taskは判断が一つかゼロになるまで分解し、新しい判断点が見つかったらそのtaskを止めて分割へ戻る。確認待ちでも進められる仕事は、その回答に依存しない別のtaskと明確にした |
| USER_ONLYの補助 | 一般規則はAIの実行を禁じるが、リリース工程の個別行は、ユーザーが依頼した整理・レビュー・検証の補助を認める | 両文書で仕事本体の代行と明示的に頼まれた補助を区別。補助を仕事本体の代行や完了の受入とは扱わない |
| 担当名と割当 | V2は役割表の読者を任命しないが、Registryの更新担当は単にCodexと書かれていた | 更新担当はその仕事を明示的に割り当てられたCodexとした。既存の担当欄の名称は変更していない |
| 完了行の扱い | 「状態が変わり得るtaskだけを残す」という説明に対し、現行表にはDONEの行がある | 履歴へ移す前の完了・除外行が残りうることと、それらを残作業・着手候補に数えないことを明記。行の削除や移動はしていない |

## 確認結果

- 進捗一覧の全表の行が修正前と一致する。作業49件のID・状態・担当・条件・参照先、依存関係18件、採番状態18種類を変更していない。
- 現行作業のIDに重複はなく、各IDの番号が記録済みの採番上限を超えていないことを確認した。Archivedを含む過去の全IDの再監査はしていない。
- 現在の律速、中間ゴール、後続目標、将来の目標候補の記述は変更していない。空欄に目的を推定で補っていない。
- 進捗一覧のtask分解、DECISION・EXECUTION・DISCOVERYの定義、新しい判断点が見つかった場合の停止・再分解の規則は、原文のまま保持した。
- 文書の権限・配置に関する既存の制限と例外は、そのまま保持した。Orientationの採用・参照切替・配置変更やUser領域の規則を緩めていない。
- V2から参照する「文書ランクと変更権限」「正本整理時の配置維持例外」「Task ID採番状態」が進捗一覧に存在することを確認した。

この確認は、二文書の規定と参照関係を対象とする。個々の開発成果や完了判定の正しさを改めて検証したものではない。
