# 正本

**何を満たせば完了か、何がその仕事を支えるかを揃える。**

- ユーザーの要求と受入条件を書く。各条件に、確認方法と期待する結果を対応させる。
- 必要な前提・既存機能・検証手段を確認し、確認済み／未確認／壊れているものを区別する。使える確認結果は引き継ぐ。
- 支えに不備があれば、後続への影響と対処を決める。許可内なら先に整え、判断が必要なら、原因・選択肢・推奨を添えて依頼する。
- 作業範囲と許可を明示する。

# 作業

**検証できる土台を整え、要求を満たす仕事をひと続きで進める。**

- 最新の要求・変更・停止指示を確認する。
- 失敗を「既存だから」で流さない。何を確かめられなくなったかを調べ、必要な支えを先に直す。
- 分割・統合は、不要なものを減らし、後続を安定させるために選ぶ。差分の小ささや分割数を目的にしない。
- 集中して扱うべき仕事を、不必要な依頼・返却や細切れの確認で分断しない。
- 変更した挙動を確認する。画面の要求は実画面でも確かめる。再確認は、変更や失敗などの理由がある範囲で行う。

# 受け入れ

**作業者が証拠付きで返し、検品・検収側はそれを照合する。**

受入条件ごとに、次の形で返す。

| 項目 | 書くこと |
|---|---|
| 要求・受入条件 | 何を満たす必要があったか |
| こうでした | 実際の結果。達成／未達／未確認 |
| 理由 | その結果をどう判断したか |
| 証拠 | 対象の版、確認方法、期待値と実測値、ログや画面への参照 |

最後に、**変更範囲・残っている問題・次に必要な判断**を短く添える。未達条件を勝手に外さず、事実と推測を分ける。

- **検品**：証拠は主張を裏づけているか。条件の抜けや矛盾はないか。
- **検収**：要求を満たしているか。残件を踏まえて受け入れられるか。

**証拠不足なら、何が足りないかを指定して返す。検品・検収側が作業者の調査や報告を作り直さなくて済む状態にする。**
